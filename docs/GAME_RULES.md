# GAME_RULES.md

이 문서는 경제 시뮬레이션의 규칙을 정의한다. 여기 있는 규칙은 [DECISIONS.md](DECISIONS.md)에
확정된 결정사항과 일관되어야 하며, 충돌 시 DECISIONS.md가 우선한다.

## 1. 경제주체

학생 한 명은 아래 세 경제주체를 각각 하나씩 가지며, 셋은 **별도의 자산과 손익**을 가진다.
한 역할의 자산을 다른 역할로 임의로 이동할 수 없다 (D-001, D-002).

### 기업 (Company)

결정 항목: 생산 품목, 생산량, 상품 품질, 생산비, 인건비, 임대료, 생산설비, 연구개발,
도매 판매가격, 유통 전략.

상품은 자동으로 가게에 판매되지 않는다. **도매시장**에 등록하고, 가게가 여러 기업의 상품을
비교해 직접 구매한다 (D-003, D-004).

### 가게 (Store)

결정 항목: 어떤 기업의 상품을 매입할지, 매입 수량, 판매가격, 상품 구성, 재고 관리, 상권,
전문화 전략, 필요 시 신규 점포 개설. 기업과 별개의 자산·손익을 가진다.

### 가계 (Household)

수행 항목: 예산 확인, 여러 가게의 상품 비교(가격/품질/필요성/선호 고려), 실제 구매, 남은
자산/저축 관리. 목표는 "많이 남기기"가 아니라 소비 만족·필요 충족·예산 관리의 종합이다.

## 2. 자기 거래 제한 (D-005, D-006)

- 자신의 기업 상품을 자신의 가게가 직접 매입할 수 없다.
- 자신의 가게에서 자신의 가계가 직접 구매할 수 없다.
- 담합 방지를 위해 필요 시 구매 단계에서 판매자 신원을 익명화할 수 있다 (가게→가계 거래).

## 3. 기본 비용 (1라운드부터 존재, D-009)

- **기업**: 인건비, 임대료, 생산비, 원재료비, 필요 시 유통비.
- **가게**: 인건비, 임대료, 상품 매입비, 유통비, 기타 기본 유지비.

## 4. 업종 변경과 유사도

기업이 기존과 다른 상품을 생산하려면 추가 비용이 발생하며, 유사도에 따라 다음과 같이 차등화한다.

- 기존과 유사한 상품 → 추가비용 낮음
- 어느 정도 관련된 상품 → 추가비용 중간
- 완전히 다른 분야 → 설비·연구개발 비용 매우 높음

상품 종류 간에는 유사도 개념(예: 유사도 매트릭스 또는 카테고리 트리 기반 거리)을 둔다. 가게도
처음 등록한 전문 업종과 지나치게 다른 상품을 팔면 전문성 감소, 소비자 신뢰 감소, 구매 가능성
감소의 불이익을 받을 수 있다. 완전히 다른 업종으로 확장하려면 신규 점포 개설(추가비용 발생)이
필요하다 (D-011).

## 5. 상권 시스템

창업 단계에서 기업과 가게의 위치를 선택한다 (D-010). 작은 도시 지도 또는 구역 기반 지도를
사용하며, 후보 상권 예시: 학교 주변, 주택가, 중심상권, 고급상권, 공업지역, 외곽.

지역별로 달라질 수 있는 요소: 임대료, NPC 소비자 수, 소비자 성향, 상품 선호, 유통거리, 유통비,
기업 입지 효율, 경쟁 정도.

**기업에 좋은 입지와 가게에 좋은 입지는 다르다.** 예: 공업지역은 기업 생산시설에 유리할 수
있고, 중심상권은 가게에 유리하지만 임대료가 높으며, 외곽은 임대료가 낮지만 소비자 방문이 적다.

## 6. NPC 시스템

부족한 경제주체는 NPC(기업/가게/소비자, 필요 시 유통업자)가 보완한다 (D-007). NPC 수는
학생 수뿐 아니라 시장 상황(업종 쏠림, 지역 쏠림)도 고려한다 (D-008). NPC는 학생과 동일한
경제 규칙을 따르며 특혜(무한자산, 무료 임대료 등)를 받지 않는다. 자세한 설계는
[NPC_DESIGN.md](NPC_DESIGN.md) 참고.

## 7. 라운드 흐름

각 라운드는 반드시 다음 순서로 진행한다 (자세한 내용은 [ROUND_FLOW.md](ROUND_FLOW.md)):

1. 전원 기업 턴 수행 → 2. 기업 턴 결과 확정 → 3. 도매시장 갱신 → 4. 전원 가게 턴 수행 →
5. 가게 턴 결과 확정 → 6. 소비시장 갱신 → 7. 전원 가계 턴 수행 → 8. NPC 소비자 행동 처리 →
9. 라운드 종료 계산 → 10. 라운드 결과 발표 → 11. 다음 라운드 시작.

같은 역할 턴 내에서는 전원이 동시에 수행하며, 한 학생이 다른 학생의 턴 종료를 기다리지 않는다.
